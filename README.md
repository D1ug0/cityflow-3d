# CityFlow 3D

Локальное Vue-приложение для демонстрации городского движения: MapLibre управляет картой и камерой, Three.js рисует автомобили и эффекты в **том же canvas и WebGL 2 context**.

## Запуск

Требуется Node.js 22.12+ (проверено с 22.22.3) и npm.

```sh
npm ci
npm run dev
```

Откройте адрес, который выведет Vite (обычно `http://127.0.0.1:5173`). Сервер сам браузер не открывает. Публикация и OpenAI Hosting не настроены.

```sh
npm run check       # ESLint, Vitest, TypeScript, production build
npm run test:watch
npm run build
npm run preview    # просмотр production-сборки локально
```

## Реализовано

- Vue 3, Composition API, TypeScript, Vite, Vue Router, Pinia.
- FSD: `app → pages → widgets → features → entities → shared`.
- Карта центра Москвы: масштаб, поворот, наклон, сброс камеры.
- MapLibre Custom Layer с общей матрицей камеры и единым render loop.
- Собственная локальная low-poly модель `public/models/car.gltf`.
- Детерминированная симуляция 100 / 1 000 / 5 000 / 10 000 автомобилей.
- Расчёт позиции по накопленным длинам сегментов LineString, скорости в км/ч и progress.
- InstancedMesh, отсечение каждого автомобиля по frustum, компактный буфер видимых экземпляров.
- Выбор кликом через raycasting с корректным соответствием instance ID и автомобиля после culling.
- GLSL-подсветка выбора, анимированный поток на дорогах, дождь через Points.
- День, закат, ночь: освещение моделей и яркость картографической подложки.
- LOW/MEDIUM/HIGH, ограничение DPR, изменение количества частиц и геометрии.
- Adaptive quality: снижение после 3 секунд низкого FPS, cooldown 8 секунд, повышение после 20 секунд стабильного FPS > 57.
- Панель метрик, пауза, мобильная выдвижная панель настроек.
- Сообщения об ошибках WebGL 2, потере контекста, карте, GeoJSON и модели; primitive fallback при ошибке GLTF.

## Данные и ограничения

**Это визуальная симуляция, а не навигационная модель или сервис пробок.**

Маршруты построены по связному графу реальных улиц OpenStreetMap из локальной выборки OpenFreeMap. Сохраняются вершины дорог и доступные признаки одностороннего движения; участки рядом со зданиями исключаются с запасом под кузов. Контуры зданий взяты из той же выборки. Симуляция пока не учитывает полосы, ограничения поворотов, светофоры и столкновения. При высокой нагрузке машины могут перекрываться. Цвет потока отражает заданную общую нагрузку, а не измеренную скорость участка.

Маршруты, здания и модель лежат в `public/` и не требуют API-ключей. Источник геоданных и лицензия описаны в [data/README.md](data/README.md). Пересборка маршрутов: `python3 scripts/build-map-data.py`. Собственная модель автомобиля создаётся отдельно: `python3 scripts/generate-demo-assets.py`. Модель использует локальные оси X-вперёд, Y-вбок, Z-вверх, размеры в метрах.

Названия улиц и настоящая картографическая подложка поступают из растровых тайлов OpenStreetMap. Для них нужен интернет. При недоступности тайлов локальные дороги, здания и симуляция остаются, подписи улиц отсутствуют. Атрибуция OpenStreetMap находится на карте. Массовая загрузка, offline-prefetch и публичный production-сервис через этот тайловый endpoint не реализованы.

На этом этапе карта использует Mercator без terrain: матрицы и высоты рассчитаны именно для этой проекции. Нет полноценного навигационного графа с правилами поворотов, пространственного индекса для автомобилей, GPU picking, постобработки bloom и полноценного сравнения Mesh vs InstancedMesh. Glow — пульсирующий шейдерный контур под автомобилем, а не screen-space bloom.

## Архитектура

```text
Vue UI / Pinia (настройки, выбор, метрики 2 раза в секунду)
  ↓
SceneController (композиция объектов, команды, события)
  ↓
ThreeMapLayer (shared: lifecycle, камера, renderer)
  ↓
MapLibre render → simulation → uniforms → instance buffers
  ↓
Three.js → общий WebGL 2 context → GPU
```

`shared/lib/three` не импортирует Vue, Pinia или сущности автомобиля. `entities/vehicle` содержит симуляцию и 3D-адаптер автомобилей; `entities/route` — валидацию и интерполяцию; `entities/traffic` — эффекты. `widgets/map-scene/SceneController.ts` собирает их, а Vue-компонент занимается lifecycle и передачей настроек.

На каждом кадре **не обновляется Pinia для всех машин**. Данные симуляции хранятся в typed arrays. В реактивное состояние попадают настройки, карточка выбранного автомобиля и статистика с интервалом 500 мс.

## Rendering и ресурсы

MapLibre вызывает `ThreeMapLayer.render`. Матрица карты умножается на локальный Mercator transform, где координаты сцены заданы в метрах вокруг центра Москвы. Перед рендером Three.js и после него вызывается `resetState()`. `autoClear` отключён: Three.js не очищает карту.

Один InstancedMesh хранит все автомобили. На кадре проверяется frustum для каждой машины; видимые матрицы компактно записываются в instance buffer, невидимые машины продолжают движение, но не отправляются на отрисовку. CPU-обход остаётся O(N), поэтому 10 000 машин ещё требуют измерений и дальнейшей оптимизации. GLTF загружается один раз для набора машин, а не отдельно для каждого экземпляра.

Качество ограничивает общий pixel ratio **через MapLibre**; Three.js не меняет размер общего canvas. На всех уровнях детализации автомобиль сохраняет кузов, кабину и колёса: LOW использует шестигранные колёса, MEDIUM добавляет детализацию и световые элементы, HIGH загружает GLTF. Дождь использует одну BufferGeometry на максимум 10 000 точек и меняет draw range согласно preset.

Выключение слоя скрывает уже выделенные ресурсы; повторное включение использует их повторно, без накопления геометрий и материалов. Смена количества машин уничтожает старый InstancedMesh и его ресурсы. При удалении custom layer/страницы освобождаются геометрии, материалы, текстуры и renderer, снимаются обработчики событий. Поздно завершившаяся загрузка модели также освобождается, если её владелец уже уничтожен. Three.js **не вызывает `forceContextLoss()`** для контекста карты.

## Метрики

В dev-режиме панель открыта по умолчанию. В production используйте `?debug=true` перед `#/` или переключатель панели.

- FPS и frame time: среднее по последним 120 интервалам кадров, включая влияние карты и симуляции.
- Min FPS: наихудший интервал в этом окне, не минимум за всю сессию.
- Three CPU submit: время вызова `renderer.render`, **не GPU time** и не полное время кадра.
- Draw calls, triangles, geometries, textures: только счётчики `Three.js renderer.info`; ресурсы MapLibre сюда не входят.
- Visible: количество экземпляров после culling, Vehicles: заданный размер симуляции.
- DPR: фактический pixel ratio MapLibre.

После возвращения на вкладку временное окно и адаптивный регулятор сбрасываются. Рост progress за один кадр ограничен 100 мс, чтобы не перескакивать далеко после простоя.

## Проверки

Vitest проверяет движение на прямых и поворотах, перевод скоростей, замыкание progress, round-trip координат, валидацию GeoJSON, нагрузки до 10 000 машин, задержки adaptive quality, frame budget, rolling average, DPR/LOD, culling с сохранением ID выбора, повторное освобождение ресурсов и последовательность MapLibre Custom Layer. Интеграционный тест слоя использует mocked WebGLRenderer и **не подтверждает визуальный результат WebGL**.

Браузер и визуальные проверки намеренно не запускались по запросу владельца проекта. Ручной сценарий:

1. Открыть `npm run dev`, дождаться карты и машин.
2. Увеличить карту до отдельных автомобилей, выбрать машину, проверить карточку и контур; закрыть карточку.
3. Вращать карту и менять наклон; убедиться, что машины сохраняют привязку к дорогам.
4. Проверить паузу, слои, дождь и время суток.
5. Переключить все четыре нагрузки и три режима качества; проверить режим на узком экране.
6. Несколько раз отключить/включить слои: число geometries/textures после прогрева должно стабилизироваться.
7. Проверить без доступа к тайлам и отдельно с недоступной моделью; должен оставаться понятный fallback.
